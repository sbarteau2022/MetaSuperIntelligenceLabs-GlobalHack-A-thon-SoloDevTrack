# Documentation Standards (Required)

Apply these standards whenever creating or editing documentation, checklists, handoffs, or audit reports.

## 1. Label every claim
- VERIFIED (measured or read from source).
- REPORTED (a source says so, unchecked).
- INFERRED (reasoned from evidence; say where evidence ends).
- PROPOSED (a plan, not a fact).
- An unlabeled claim is treated as unverified.

## 2. Evidence or it didn't happen
- Performance numbers need context: hardware, settings, workload, comparison number.
- "Done" requires the checker's output, not a summary.

## 3. Corrections are entries, not edits
- When a claim turns out wrong, append a dated correction naming what it replaces.
- Never silently rewrite history; never delete the wrong claim without withdrawing it in the same breath.

## 4. Five-file set per workstream
- Design.md (what and why), Pre-Registration.md (predictions/judges before the run), CLAIMS_REGISTER.md, Successes.md, Failures.md.
- A failure recorded is worth more than a success asserted.

## 5. Write for the next reader
- Date everything; name files, paths, versions exactly.
- State what was NOT checked.
- Keep entries tight: finding, evidence, consequence — in that order.

## 6. No bulk anything
- No bulk deletes, no bulk rewrites, no batch claims.
- Per-item disposition, per-claim evidence.

## When to invoke
- Always invoke this skill when creating, editing, or reviewing documentation.
- Do not stop a turn without applying these standards to any docs touched.
